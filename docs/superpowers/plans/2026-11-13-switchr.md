# Switchr Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pick, per agent terminal, which Claude Code / Codex account it runs on; move an idle session to another account in place, keeping the conversation; see the account in the Agents list.

**Architecture:** A Python CLI `switchr.py` (beside `bridge.py`) owns account homes (a folder per extra account whose entries symlink to the main `~/.claude` / `~/.codex`, except the login), launching agents into them, reading limits, reporting which account each live agent uses, and moving a session. The Powr mod gets a Switchr page and a move popup and polls `switchr.py which`. The Agents list badge comes from a local clone of Herdr's own `agents` mod, made and patched by the installer (Herdr's code is never shipped in this repo).

**Tech Stack:** Python 3.9+ stdlib (unittest), Herdr desktop mod JS (gpui-kit), `hc` CLI, node --test.

**Spec:** `docs/superpowers/specs/2026-11-12-switchr-design.md`

## Global Constraints

- Public, generic tool: any number of accounts per kind, named by the person; nothing specific to one user's accounts in code, tests or docs.
- Main account = `~/.claude` (+ `~/.claude.json`) and `~/.codex`, never written by Switchr; main agents run with no `CLAUDE_CONFIG_DIR` / `CODEX_HOME`.
- Extra homes: `${XDG_DATA_HOME:-~/.local/share}/switchr/<kind>/<name>/`, mode 700. Registry: `${XDG_DATA_HOME:-~/.local/share}/switchr/accounts.json`.
- Kinds: `claude`, `codex` only. Local machine only.
- Never two homes holding the same identity (Claude: `email`+`orgId` from `claude auth status`; Codex: `email`+`account_id` from `auth.json` id_token claims / tokens).
- Moving a session only when the agent status is `idle` or `done`. Never start a fresh conversation silently; on failure leave the shell and say so.
- Account names: `^[a-z0-9][a-z0-9-]{0,23}$`.
- Every test that touches homes runs under a temp `HOME` / `XDG_DATA_HOME` (see `sandboxed_state()` in `tests/test_bridge.py` for why).
- Run only the touched test files mid-work (`python3 -m unittest tests.test_switchr_x -v`); `scripts/check.sh` at the end.
- Commits: English, conventional prefix, end with the two attribution lines used in this repo's recent commits.

## Review Focus

1. **Main folder gains a new entry after an extra home was made** (Claude creates a new dir after an update) — the next `switchr.py run` links it; a stale dangling link in the extra home is removed. → test in Task 1.
2. **Main `~/.claude.json` absent or mid-write (invalid JSON)** — `run` keeps the extra home's existing file and still starts the agent. → test in Task 1.
3. **Agent quits slowly or not at all on move** (a dialog open, a hung process) — move waits at most 20 s, then reports failure and types nothing more into the terminal. → test in Task 4.
4. **Original argv carries resume flags** (`--resume`, `-r <id>`, `--continue`, `-c`, `codex resume <id>`) — they are dropped and replaced by the one resume of the current conversation; other flags (`--dangerously-skip-permissions`, `--model x`) kept in order. → test in Task 4.
5. **Account name collision or removal while an agent runs on it** — `add` refuses an existing name; `remove` refuses while any process runs with that home. → test in Task 2.

Claude: `session` = `percent` of the `limits` item with `group == "session"`, `week` = max `percent` of items with `group == "weekly"`, `resets` = `resets_at` of the item giving `week`. ### Task 4: Which account each agent is on, and moving a session

  - `resume_argv(kind, argv: list[str], session: str) -> list[str]` — argv without argv[0], with resume/continue flags removed (claude: `--resume X`, `--resume=X`, `-r X`, bare `--resume`/`-r` when followed by another flag or nothing, `--continue`, `-c`; codex: leading `resume [ID]` subcommand and `--last`), then the resume added (claude: `--resume <session>`; codex: `resume <session>` first).

Codex: **verify first** with a live Codex: look for the open rollout file in `/proc/<pid>/fd` (`.../sessions/**/rollout-*-<uuid>.jsonl`) and take the uuid; record what was found in a comment.

Messages are plain sentences ("Moved to bonus, same conversation." / "Still working — try when it has finished." / "The agent did not quit within 20 seconds; nothing was changed.").
